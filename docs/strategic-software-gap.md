# 国家战略软件方向：ai-hub 能力与缺口核对

**[中文](./strategic-software-gap.md) · [English](./strategic-software-gap.en.md)**  
核对日期：2026-10-06；对象：本仓库当前 101 个独立项目。这里的“国家战略软件”是对政策中软件重点方向的便捷称呼，**不是官方产品认证、项目申报目录或覆盖率排名**。目录存在、依赖某项技术、通过构建，均不能算掌握其核心软件能力。

1. [国家发展改革委刊载《中华人民共和国国民经济和社会发展第十五个五年规划纲要》专栏 2](https://www.ndrc.gov.cn/fggz/fzzlgh/gjfzgh/202603/U020260317369114704096.pdf)（2026-03）：其中“基础软件和工业软件”明确列出操作系统、数据库、中间件、编程语言及编译器、开发测试工具、云计算软件，以及研发设计、生产控制、经营管理三类工业软件；[省政府转载的规划全文](https://www.hubei.gov.cn/szyw/202603/t20260314_5892205.shtml)另述人工智能、工业互联网、数据及安全等任务。

3. [工信部《“十四五”软件和信息技术服务业发展规划》通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2021/art_587ca7f076db43a499400525e0c6a244.html)（2021-11-30，**历史规划**；[解读](https://www.miit.gov.cn/jgsj/xxjsfzs/xxfwy/art/2021/art_bfd0f3934e4b40b4a0f4cdb6d747c72d.html)）：用于交叉检查基础、工业、新兴平台、行业应用和嵌入式软件，不冒充 2026 年新政策。

[现有产品矩阵](./product-matrix.md)的四项是**软件业收入统计方向**；本页核对的是**技术与产品能力方向**。两张表不能逐列相加，行业应用多也不能抵消底层软件空白。

## 逐项核对

状态含义：**空白**=未发现该类核心交付；**样板**=有相关本机界面/流程但缺关键能力；**试点**=有局部可运行实现、尚不能跨项目复用。以下为仓库能力判断，不是对外部企业技术水平的判断。

| 战略方向 | 现有相关项目与真实范围 | 核心缺口 / 状态 | 首个可验证里程碑 |
| :--- | :--- | :--- | :--- |
| 操作系统、数据库、中间件 | 各项目使用 Java、Spring Boot、本机 JSON；这是**使用**技术栈，不是研制内核 | 内核、事务、查询优化、消息/服务治理均**空白** | 不以“新增目录”充数；若选数据库方向，先界定最小查询/事务模型，持久化及并发一致性测试，再独立评估研发投入 |
| 编程语言、编译器、开发测试工具 | [测试管理](../testops/README.md)存手工用例和结果；[智能工具](../ai/README.md)生成可复制命令，不自动执行 | 解析、编译、调试器及自动化测试执行器**空白** | 先把测试管理做成受隔离的测试执行与报告服务：超时、退出码、日志、失败回放、安全白名单用例 |
| 云计算/新兴平台软件 | [运维](../itops/README.md)等是独立本机应用 | 资源调度、租户隔离、弹性、计量和服务等级保障**空白** | 先证明两个真实租户的数据隔离、资源限额和故障恢复，再谈平台能力 |
| 工业研发设计软件 | [实验记录](../labbook/README.md)、[质量管理](../qms/README.md)为记录工作台 | 计算机辅助设计/工程、仿真、工艺建模、产品全生命周期模型**空白** | 只选一个明确工艺/模型问题：可输入、复算、与已知样本比对并可导出结果；不要把表单称为仿真软件 |
| 工业生产控制软件 | [制造执行](../manufacturing/README.md)只有物料与工单的手工记录；[仓储](../wms/README.md)也为本机记录 | 实时采集、设备接入、排程执行、过程追溯和断连恢复**样板** | 在离线设备模拟器上跑工单下发→状态采集→异常处理→追溯闭环，重启/重复消息/断线恢复均有测试；真实设备另验收 |
| 工业经营管理软件 | [企业资源管理](../erp/README.md)、[供应链](../procurement/README.md)等有档案/关联记录 | 财务库存一致性、跨模块事务、多角色审批、审计及集成**样板** | 最小采购→入库→库存→结算闭环，校验重复请求、并发扣减、权限拒绝和冲正 |
| 嵌入式及设备侧软件 | [门禁](../access/README.md)、[通信设施](../telecom/README.md)为网页管理记录 | 固件、设备协议、离线缓存、安全升级、硬件在环**空白** | 从一款具体设备及协议开始，模拟器测试安全握手、断网重连与升级回滚；硬件验收另列证据 |
| 人工智能与软件融合 | [智能工具](../ai/README.md)提供命令/技能/提示词模板，不连接模型 | 模型网关、可审计推理、权限边界、输出评测、工具调用防护**样板** | 可选模型网关先在隔离样例数据上完成鉴权、超时、费用限额、敏感信息拒绝、基线评测和人工复核；不默认上传业务数据 |
| 数据安全与可信应用底座 | [管理后台](../manage/README.md)仅外部签发者的 JWT API 校验**试点**；其余项目无统一鉴权，[盘点](./auth-integration.md) | 浏览器登录、服务端角色/数据权限、密钥轮换、审计与敏感数据保护**未交付** | 优先贯通一个业务项目的网页登录、资源级 401/403、越权回归、审计和会话过期，再抽取可复用配置；不能直接开放公网 |
| 行业应用软件 | [分类目录](./project-catalog.md)涵盖医疗、教育、零售、能源等业务入口 | 多数是单用户本机记录；真实支付、诊疗、监管、多人协作等**样板** | 每个拟上线行业先列用户、真实流程与法规边界，完成浏览器/设备端到端、安全、备份恢复和真实用户验收 |

## 建设顺序，而非再造空壳

1. **先修共性安全和测试**：以一个现有业务项目做认证/授权/审计闭环；补自动化执行的隔离与失败证据。没有这些条件，不扩大敏感业务的部署承诺。
2. **再做一条工业闭环**：优先在现有制造执行项目内增加设备模拟器、工单状态机和追溯，测试失败恢复；明确这仍不是工业控制系统或真实工厂认证。
3. **最后评估高成本底座研发**：操作系统、数据库、编译器、设计仿真需要独立技术路线、领域专家和长期基准验证，不承诺用 Vue + Java 21 的页面工程快速填满。现有统一技术栈适合业务应用与管理界面，底层/设备核心可使用其他适合的语言及运行时。

**核对方法与限制：**逐项目目录及现有 README/鉴权盘点做功能级比对；本轮为文档核对，没有重跑 101 项业务流程、真机或硬件测试。项目名称和截图仅证明有入口，不证明生产可用。[验证记录](./project-validation-2026-10-03.md)记录了与本页不同的测试范围。后续每完成一项能力应附可运行命令、用例、失败测试、截图/日志及明确限制，然后再更新状态。
