## 每轮要问的问题

1. 用户能不能按 README 在对应操作系统直接启动？脚本是否检查失败并给出有效错误？
2. 页面、接口、测试、截图是否真实一致？能否在干净数据目录复现？
3. 新增业务是否有足够深度，还是只有两个通用表格？不要为了数量增加空壳。
4. 敏感行业的本机、单用户、无鉴权边界是否清楚，是否避免真实数据与公网部署误导？
5. CI 是否覆盖本轮改动、报告可信，是否区分构建检查与端到端业务验收？
6. 中文/英文说明、端口、文件链接、截图和项目数量是否一致？

## 已知后续重点

- 87 个项目的前端交互自动化覆盖仍不均衡；定时 CI 只验证构建、后端测试和 jar 静态资源，不能代替浏览器与真实业务流程测试。
- 许多行业项目仍是本机单用户 JSON 记录样板；鉴权、权限、并发、备份恢复和行业流程需要针对真实需求逐项建设，不能默认升格为生产系统。
- 首次远端完整 87 项 CI 结果尚未确认；确认之前不要写“全量 CI 通过”。
